# Story 1.3: 前端数据源管理页面

Status: done

## Story

As a **管理员**,
I want **通过 Web 界面查看、新增、编辑和删除数据源**,
so that **无需直接操作数据库即可管理数据源配置**。

## Acceptance Criteria

1. **列表展示**
   - Given 管理员进入数据源管理页面
   - When 页面加载完成
   - Then 以表格形式展示所有数据源，列包含：名称、编码、类型、主机、端口、用户名、密码、操作
   - And 密码列默认显示 `***`，点击眼睛图标切换明文/掩码
   - And 空状态时显示"暂无数据源"

2. **按名称模糊查询**
   - Given 管理员在搜索框输入名称关键字
   - When 点击"查询"按钮
   - Then 列表过滤显示名称匹配的数据源
   - And 点击"重置"按钮清空搜索条件，恢复全量列表

3. **新增数据源**
   - Given 管理员点击"新增数据源"按钮
   - When 弹出 Modal 表单
   - Then 表单字段一行两个排列，包含：名称、编码、主机、端口、库名、账号、密码、数据库类型（下拉）
   - And 编码字段提示"每个数据源的编码唯一，不可重复"
   - And 保存成功后显示 Toast "保存成功"
   - And 编码已存在时显示对应错误提示

4. **编辑数据源**
   - Given 管理员点击列表中某行的"编辑"
   - When 弹出 Modal 表单
   - Then 所有字段回填已有数据，密码明文回显

5. **删除数据源**
   - Given 管理员点击某行的"删除"
   - When 弹出确认对话框
   - Then 确认后删除该数据源，显示 Toast "删除成功"

### 关键设计决策

- **密码显隐**：列表和表单中使用 `type="password"` + 眼睛图标切换，由前端控制，后端返回明文（按 NFR3）
- **Modal 表单**：新增/编辑使用同一 Modal，通过 `isEdit` 区分模式；编辑时通过 props/emit 传递数据
- **编码唯一性校验**：提交时后端返回 `code: 400`，前端通过 `ApiResponse.code !== 0` 检测并显示错误
- **不分页**：列表一次性加载全部数据（架构决策 AR8）
- **字段布局**：表单字段一行两个（grid 两列布局），减少滚动
- **数据流**：组件内部状态管理，无需 Pinia/Vuex store
- **删除确认**：使用 `window.confirm()` 或 `Element Plus` 的 ElMessageBox（如已引入），简单场景用 `confirm()`

### 后端 API 端点参考

| 端点 | 方法 | 说明 |
|------|------|------|
| `GET /api/v1/datasources?name=xxx` | list | 列表查询（可选 name 参数模糊搜索） |
| `POST /api/v1/datasources` | create | 创建数据源 |
| `PUT /api/v1/datasources/{id}` | update | 更新数据源 |
| `DELETE /api/v1/datasources/{id}` | delete | 删除数据源 |

后端响应格式：`{ code: 0, msg: "success", data: ... }`，业务错误返回 `{ code: 400, msg: "code already exists", data: null }`
